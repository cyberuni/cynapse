title: Library API
description: Use cynapse as a library — open a store, create channels, append and read entries from TypeScript.
---

Everything the [CLI](/cynapse/cli/) does is a thin shell over a `Store`. The package exports that
store, its types and its helpers, so a tool can read and write channels directly instead of shelling
out to the `cynapse` binary and parsing its output.

## Install

```bash
npm install cynapse
```

:::caution[Prototype]
npm has only a `0.0.0` placeholder so far, and the `Store` interface isn't a stable
contract until the first real release. Until then, depend on a clone of the repository.
:::

`cynapse` is ESM-only and ships its own types. The store uses Node's built-in
[`node:sqlite`](https://nodejs.org/api/sqlite.html), so there is no native module to build; it needs a
Node.js release that includes it (the package builds for Node 22).

The `Store` types are re-exported with `export type *`, so they are available as type-only imports.
The CLI entry itself (`cynapse` the binary) is not importable.

## Example

Open a store, create a channel, append an entry, and read it back as another participant.

```ts
import { openStore } from 'cynapse'

// ':memory:' is a throwaway store. Omit `path` to use $CYNAPSE_HOME/cynapse.db.
const store = openStore({ path: ':memory:' })

const channel = store.createChannel({
  handle: 'release-1.0',
  type: 'demo.release',
  title: 'Release 1.0',
  author: 'alice',
})
store.addMember(channel.handle, 'bob', 'reviewer', 'alice')

const entry = store.append('release-1.0', {
  author: 'alice',
  type: 'demo.note',
  body: 'Cutting the release branch.',
  tags: ['demo.status'],
  refs: ['gh:cyberuni/cynapse#12'],
})
console.log(`${entry.channel}#${entry.seq}`, entry.id)
// release-1.0#3 01a10a48-099a-70e9-9b4c-bc294e541315

console.log(store.unread('bob'))
// [{ channelId: '01a10a48-…', handle: 'release-1.0', count: 3 }]

for (const e of store.entries('release-1.0', { unreadFor: 'bob' })) console.log(e.seq, e.type)
// 1 cynapse.channel.created
// 2 cynapse.member.joined
// 3 demo.note

store.markRead('release-1.0', 'bob')
console.log(store.unread('bob')) // []

console.log(store.entry(`release-1.0#${entry.seq}`)?.tags) // [ 'demo.status' ]
store.close()
```

Notice that the entry is `#3`, not `#1`: creating a channel and adding a member are themselves
entries (`cynapse.channel.created`, `cynapse.member.joined`), because the log records every change to
channel metadata. See [Entries](/cynapse/concepts/entries/).

A store holds an open database connection: call `close()` when you are done. The CLI does this for
you in a `finally`.

## Failures

Operations that cannot proceed throw a [`CynapseError`](/cynapse/api/ids/#errors) with a message that
names what failed (`no channel found for "nope"`) and, for conflicts, a stable `code` such as
`id_conflict`. The library never calls `process.exit` and never writes to stdout; only the CLI does.

:::note
There is no `registerParticipant`, address resolution, sync or hub in the library yet. They are
designed but not built.
:::
