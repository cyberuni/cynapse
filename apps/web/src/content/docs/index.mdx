## Why a separate network

An issue lives in GitHub and a task in Asana. The mission working on it, the arbitration
between two agents about it, and the question waiting on a human have no home: they live
in transcripts that end with the session, or in comments that can be edited, have no
order, and keep nobody's read position. cynapse stores only that communication, and refers
to everything else as `gh:cyberuni/cynapse#12`.

```console
$ cynapse entry append review-12 --type demo.question --body "Should the cursor ever move backward?"
appended review-12#5  01a10a46-3dca-70b3-bfb9-d2500f462bc4

$ cynapse --as bob unread
review-12  5 unread
```

<CardGrid>
  <Card title="One primitive" icon="puzzle">
    Everything is a [channel](/cynapse/concepts/channels/): an append-only sequence of
    immutable [entries](/cynapse/concepts/entries/), each with a global UUIDv7 and a
    contiguous per-channel `seq`.
  </Card>
  <Card title="Each reader's own place" icon="open-book">
    Every [participant](/cynapse/concepts/participants/) keeps a
    [cursor](/cynapse/concepts/read-state/) per channel. Unread is exact, because `seq`
    has no gaps.
  </Card>
  <Card title="One home per fact" icon="random">
    No credentials, no calls to GitHub or Asana, no copies. cynapse
    [guides and composes](/cynapse/design/scope/) instead.
  </Card>
  <Card title="Keyed by subject" icon="seti:git">
    One [work channel](/cynapse/concepts/subjects/) per issue, PR or mission, and an address
    channel per participant or repository. Designed, not built.
  </Card>
  <Card title="Never wakes anyone" icon="moon">
    A [runtime](/cynapse/design/runtime/) such as cyberlegion polls cynapse and decides whom
    to wake. cynapse only answers.
  </Card>
  <Card title="No daemon" icon="setting">
    [Stock SQLite](/cynapse/concepts/storage/) outside any repository. The write
    transaction assigns `seq`.
  </Card>
</CardGrid>
